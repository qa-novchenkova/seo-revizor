Что это

Обычный SEO-аудит делают руками по списку: открыть robots.txt, посмотреть заголовки, проверить зеркала, прокликать ссылки. Работа механическая, но пропустить пункт легко, а цена пропуска высокая — одна строка в robots.txt закрывает сайт от поиска целиком.

Ревизор состоит из двух частей. Сервер — набор функций, каждая проверяет свой участок и возвращает данные. Агент — цикл, который сам решает, какую функцию вызвать следующей, исходя из того, что нашлось на предыдущем шаге. Карта сайта нашлась — берём из неё страницы; не нашлась — идём по ссылкам с главной. Сколько будет вызовов, заранее не знает никто.

Сервер работает на вашей машине и никуда ничего не отправляет. Проверять чужие сайты без разрешения владельца не стоит: обход создаёт нагрузку.

Инструменты

Ровно то, что сервер отвечает на вопрос «какие у тебя есть инструменты». Описания читает модель — по ним она понимает, когда какой вызывать.

Проверка адреса

check_url

Проверяет один адрес: код ответа сервера, полную цепочку редиректов, ключевые заголовки и время ответа. Вызывай, когда нужно узнать, что сервер отдаёт по конкретному URL: жив ли адрес, куда он ведёт, сколько редиректов по дороге.

Мета-теги и заголовки страницы

check_meta

Скачивает страницу и разбирает её содержимое: title, описание, заголовки H1–H6 и их иерархию, canonical, мета-тег robots, разметку Open Graph, микроразметку Schema.org, атрибуты alt у изображений. Вызывай для проверки конкретной страницы на месте.

Файл robots.txt

check_robots

Скачивает и разбирает robots.txt: группы правил, запреты, директивы Sitemap. Отдельно проверяет, не закрыт ли сайт от индексации целиком. Вызывай первым при аудите нового сайта: здесь находятся самые тяжёлые ошибки, а заодно выясняется адрес карты сайта.

Карта сайта

check_sitemap

Разбирает sitemap.xml и возвращает список адресов страниц. Понимает карту карт (sitemapindex) и заглядывает внутрь. Проверяет дубли, чужие домены, адреса с параметрами, наличие дат изменения. Отдельно возвращает поле sample — представительную выборку: по одной странице каждого типа (главная, раздел, карточка, статья). Для поштучной проверки бери адреса именно оттуда, а не первые из общего списка: иначе проверишь десять однотипных страниц.

Внутренние ссылки

check_links

Собирает ссылки со страницы и проверяет их: битые, ведущие на переадресацию, без текста, с неинформативным текстом вроде «подробнее», с атрибутом nofollow. Отдельно показывает структуру: какие разделы вообще видны в разметке. Вызывай, когда нужно понять связность сайта — например, если на главной не видно ссылок на каталог, и непонятно, беда это сайта или её просто рисуют скриптами.

Зеркала и дубли адресов

check_mirrors

Проверяет, не видит ли поисковик вместо одного сайта несколько копий: адрес с www и без, версия по http, технические дубли главной вроде /index.php, слэш на конце, параметры в адресе, а также отдаёт ли несуществующая страница честный код 404. Вызывай в начале аудита: пока сайт двоится, остальные правки почти бессмысленны.

Безопасность

check_security

Смотрит срок и корректность сертификата, защитные заголовки, атрибуты cookie, смешанное содержимое, доступность служебных файлов вроде .git и .env, открытый список файлов в папках и показ подробностей ошибки на боевом сервере. Раздел, который в SEO-аудитах обычно пропускают, а находки там заметные.

Аналитика

check_analytics

Ищет системы аналитики в разметке: Яндекс.Метрика, Google Analytics, Tag Manager и другие. Проверяет, не задвоен ли счётчик, не грузится ли синхронно и стоит ли он на других страницах тоже. Без счётчика нельзя ответить на вопрос «что сработало».

Контент и дубли

check_content

Сравнивает несколько страниц между собой: одинаковые title и описания, повторяющийся текст, слишком короткие и пустые страницы, остатки демонстрационного текста, расхождения в телефонах. Единственная проверка, которой нужна не одна страница, а набор: дубли по определению видны только при сравнении. Передавай адреса из выборки, которую вернул check_sitemap, или из обхода ссылок.

Скорость и Core Web Vitals

check_speed

Измеряет скорость через бесплатный сервис PageSpeed Insights: общая оценка, LCP, CLS, INP, время ответа сервера, а также что именно тормозит — блокирующие ресурсы, тяжёлые картинки, лишний код, отсутствие кеширования. Требует бесплатного ключа: без него честно скажет, что раздел пропущен.

Чек-лист проверок

list_rules

Возвращает список всех правил, по которым работает ревизор: идентификатор, важность, формулировку, объяснение «почему это плохо» и «что делать». Вызывай, когда нужно понять, что вообще умеет проверять инструмент, или объяснить пользователю смысл конкретной находки по её идентификатору.

Порядок проверки

Последовательность не случайная: каждый шаг опирается на предыдущий. Зеркала идут первыми, потому что пока поисковик видит вместо одного сайта три копии, остальные правки почти бессмысленны.

  1. check_mirrors — не двоится ли сайт: адрес с www и без, версия по http, технические дубли главной, слэш на конце, параметры, честный ли код 404. Пока сайт двоится, остальные правки почти бессмысленны, поэтому это первый вызов.
  2. check_robots — там самые тяжёлые ошибки, и оттуда же выясняется адрес карты сайта.
  3. check_sitemap, если карта есть. Для дальнейшей проверки бери адреса из поля sample: это по одной странице каждого типа. Не бери первые адреса из общего списка urls — так проверишь десять однотипных страниц.
  4. Если карты нет, структуру покажет check_links по главной: какие разделы видны в разметке.
  5. check_meta и check_url для двух-четырёх страниц из выборки, обязательно включая главную.
  6. check_links для главной: битые ссылки, ссылки через переадресацию, тексты ссылок. Если разделов подозрительно мало, повтори с depth: 2.
  7. check_security — сертификат, защитные заголовки, cookie, доступность служебных файлов. Достаточно одного вызова на сайт.
  8. check_analytics для главной, передав в alsoCheck две-три другие страницы: так видно, стоит ли счётчик везде.
  9. check_content со списком из четырёх-восьми адресов выборки: одинаковые title и описания, повторяющийся текст, пустые страницы. Эта проверка работает только на наборе страниц, одной ей мало.
  10. check_speed для главной. Если ключа нет, инструмент честно скажет об этом — просто отметь в отчёте, что раздел не проверен.
  11. Если увиденное вызывает подозрение — проверь дополнительно. Например, при странном canonical посмотри соседнюю страницу того же типа.
  12. Когда данных достаточно, остановись и напиши отчёт. Восемь-двенадцать вызовов обычно хватает.

Индексация и техническая база 20

С этого начинается любой аудит. Пока поисковик видит вместо одного сайта три копии, всё остальное не имеет смысла.

  1. Единое зеркало сайта

    авто

    Для поисковых систем адрес с www и без www — два разных сайта. Пока склейка не зафиксирована, вес размазывается между ними, а основное зеркало может неожиданно смениться.

    Как проверитьЗапросить оба варианта, сверить код ответа и заголовок Location: должен быть один 301 на выбранный вариант.

  2. HTTPS без цепочек

    авто

    Переход с http на https должен занимать один редирект. Цепочка из двух-трёх шагов теряет время и часть ссылочного веса.

    Как проверитьПройти по цепочке редиректов от http-версии и посчитать количество шагов.

  3. Технический дубль главной

    авто

    Адреса вида /index.php, /index.html, /home открывают ту же главную. Такой дубль может выйти в поиске вместо настоящей главной.

    Как проверитьЗапросить типовые адреса и проверить, что каждый отдаёт 301 на корень.

  4. Слэш на конце адреса

    авто

    Версии со слэшем и без — разные URL. Нужен один канонический вариант, второй уводится редиректом.

    Как проверитьЗапросить обе формы для нескольких страниц и сверить коды ответа.

  5. robots.txt существует и корректен

    авто

    Одна лишняя строка Disallow способна закрыть от индексации весь сайт. Это самая частая катастрофическая ошибка после релиза.

    Как проверитьСкачать файл, проверить код 200, разобрать директивы, отдельно проверить, не закрыты ли разделы каталога и карточки.

  6. Директива Sitemap в robots.txt

    авто

    Так поисковик находит карту сайта без ручного добавления в вебмастер.

    Как проверитьНайти строку Sitemap: и проверить, что указанный адрес открывается.

  7. sitemap.xml валиден и актуален

    авто

    В карте должны быть только страницы, отдающие 200 и открытые для индексации. Мусор в карте снижает доверие к ней.

    Как проверитьРазобрать XML, выборочно проверить коды ответа из карты, сверить даты lastmod с реальными изменениями.

  8. Canonical на каждой странице

    авто

    Без canonical любые параметры в адресе плодят дубли. Обычная страница должна ссылаться сама на себя.

    Как проверитьВытащить link rel=canonical и сравнить с текущим адресом.

  9. Параметры в адресах не плодят дубли

    авто

    Идентификаторы, метки рекламных кампаний и фильтры создают сотни копий одной страницы и размывают поведенческие факторы.

    Как проверитьСобрать внутренние ссылки, найти адреса с параметрами, проверить наличие canonical и правил в robots.

  10. Пагинация размечена по стратегии

    авто + глазами

    У страниц со второй и дальше должны быть свои мета-теги. Схлопывать их canonical на первую или нет — решается осознанно, а не случайно.

    Как проверитьНайти страницы пагинации, сверить title, description и canonical между ними.

  11. 404 отдаёт именно 404

    авто

    Частая ошибка: несуществующая страница показывает текст «не найдено», но отдаёт код 200. Поисковик индексирует тысячи таких пустышек.

    Как проверитьЗапросить заведомо несуществующий адрес и проверить код ответа.

  12. Свой шаблон страницы 404

    глазами

    Пользователь не должен упираться в тупик. На странице нужны ссылки на основные разделы и поиск.

    Как проверитьОткрыть несуществующий адрес и посмотреть, что видит человек.

  13. Ошибка 500 обрабатывается

    глазами

    Белый экран с текстом ошибки сервера выдаёт технические подробности и пугает пользователя.

    Как проверитьПроверить, настроен ли собственный шаблон для серверных ошибок.

  14. Last-Modified и корректная дата

    авто

    Заголовок помогает поисковику понимать, что переобходить, и экономит краулинговый бюджет.

    Как проверитьПрочитать заголовок ответа и сравнить дату с реальной датой правки.

  15. Кодировка в заголовке совпадает с содержимым

    авто

    Расхождение даёт кракозябры у части пользователей и мешает разбору текста.

    Как проверитьСверить charset в Content-Type и в мета-теге страницы.

  16. Человекопонятные адреса

    авто + глазами

    Читаемый адрес попадает в сниппет, лучше запоминается и переносит смысл запроса.

    Как проверитьПроверить адреса на латиницу, отсутствие идентификаторов и осмысленность.

  17. Битые внутренние ссылки

    авто

    Ссылки в никуда тратят краулинговый бюджет и раздражают людей.

    Как проверитьОбойти сайт, собрать ссылки, проверить коды ответа каждой.

  18. Внутренние ссылки без редиректов

    авто

    Ссылка на адрес, который редиректит, — лишний шаг для робота и пользователя. Правится в шаблоне.

    Как проверитьНайти внутренние ссылки, отдающие 301 или 302, и заменить на конечные адреса.

  19. Мусор в индексе

    сервисы

    Тестовые копии, версии для печати, служебные разделы не должны попадать в поиск.

    Как проверитьПроверить поисковый оператор site: и сверить число страниц с числом реальных.

  20. Noindex не стоит по ошибке

    авто

    Забытый после разработки запрет индексации выкидывает страницу из поиска целиком.

    Как проверитьПроверить мета robots и HTTP-заголовок X-Robots-Tag на важных страницах.

Мета-теги и заголовки 17

Самый быстрый источник заметного результата: правки в title и H1 дают эффект раньше всего остального.

  1. Title есть на каждой странице

    авто

    Без title поисковик подставляет что попало, и сниппет теряет привлекательность.

    Как проверитьСобрать title со всех страниц, отфильтровать пустые.

  2. Title уникальны

    авто

    Одинаковые заголовки у разных страниц — прямой сигнал дублирования, часть страниц выпадет из поиска.

    Как проверитьСгруппировать title и найти повторы.

  3. Title длиннее 30 символов

    авто

    Слишком короткий заголовок не вмещает дополнительные запросы. Не критично, но это упущенная возможность.

    Как проверитьПосчитать длину и вывести список коротких.

  4. Title не обрезается в выдаче

    авто

    Примерно после 60–70 символов хвост заголовка не показывается, и важное может не дойти до пользователя.

    Как проверитьПосчитать длину в символах и в пикселях для типового шрифта выдачи.

  5. Description есть и уникален

    авто

    Описание не влияет на позиции напрямую, но определяет, кликнут по вашей строке или по соседней.

    Как проверитьСобрать description, найти пустые и повторяющиеся.

  6. Description не дублирует title

    авто

    Пользователь дважды читает одно и то же вместо того, чтобы получить причину кликнуть.

    Как проверитьСравнить строки на совпадение и высокое сходство.

  7. Ровно один H1

    авто

    Два и более заголовка первого уровня выглядят как попытка переспама.

    Как проверитьПосчитать теги h1 на странице.

  8. H1 не совпадает дословно с title

    авто

    Совпадение один в один — упущенная возможность охватить дополнительные формулировки запроса.

    Как проверитьСравнить строки, вывести полные совпадения.

  9. Иерархия заголовков без пропусков

    авто

    Уровни идут по порядку от большего к меньшему. Пропуск ломает структуру документа и мешает программам чтения с экрана.

    Как проверитьПостроить дерево заголовков и найти скачки уровней.

  10. H1 раскрывает содержимое

    глазами

    Заголовок «Девочкам» не говорит поисковику ничего. «Детская одежда для девочек» говорит всё.

    Как проверитьПросмотреть заголовки категорий и оценить, понятны ли они без контекста.

  11. Названия карточек уникальны

    авто

    Два товара с одинаковым названием поисковик считает дублями и оставляет в поиске только один.

    Как проверитьСгруппировать заголовки карточек и найти повторы.

  12. В названиях нет технического мусора

    авто + глазами

    Сокращения и слэши вида «Костюм д/мал L001 /серый/» выглядят спамно и плохо читаются человеком.

    Как проверитьНайти заголовки со спецсимволами и сокращениями, переписать по единому образцу.

  13. Настроены шаблоны генерации мета

    глазами

    Руками тысячу карточек не заполнить. Шаблон на основе H1 плюс коммерческие добавки закрывает объём.

    Как проверитьПроверить в админке правила генерации и точечные исключения.

  14. Alt у изображений заполнен и осмыслен

    авто + глазами

    Alt участвует в поиске по картинкам и читается вслух программами для незрячих. Пустой alt у баннера — потерянный трафик.

    Как проверитьСобрать изображения, найти пустые и шаблонные alt.

  15. Микроразметка Schema.org

    авто

    Даёт расширенный сниппет: цену, наличие, рейтинг, хлебные крошки прямо в выдаче.

    Как проверитьПроверить наличие разметки Organization, BreadcrumbList, Product и её валидность.

  16. Open Graph для ссылок в соцсетях

    авто

    Без разметки ссылка в мессенджере выглядит голой строкой и её реже открывают.

    Как проверитьПроверить og:title, og:description, og:image и доступность картинки.

  17. Коммерческие слова на нужных страницах

    глазами

    Слова «купить», «цена», «доставка» на страницах каталога и карточек добавляют охват коммерческих запросов.

    Как проверитьПросмотреть тексты категорий и карточек на наличие естественных вхождений.

Контент и дубли 10

Дубли бывают внутренние и внешние. Внутренние обычно создаёт сама система, внешние приходят от поставщиков и копирующих конкурентов.

  1. Внутренние дубли текста

    авто

    Одинаковые описания на разных страницах заставляют поисковик выбирать одну и отбрасывать остальные.

    Как проверитьРазбить тексты на короткие фрагменты и посчитать пересечение между страницами.

  2. Копии текстов на других сайтах

    сервисы

    Описания от поставщика стоят на сотне сайтов. Уникальный текст даёт преимущество в этой сотне.

    Как проверитьПроверить выборку абзацев через сервисы поиска заимствований.

  3. Шаблонный демо-контент

    авто + глазами

    После разработки часто остаются страницы вроде «Наша компания на рынке с 1999 года» из демо-набора CMS. Это прямой удар по доверию.

    Как проверитьНайти страницы с типовыми фразами из стандартной поставки CMS.

  4. Пустые страницы и заглушки

    авто

    Раздел без содержимого попадает в индекс и портит общую оценку сайта.

    Как проверитьНайти страницы с объёмом текста ниже порога.

  5. Тонкий контент на продвигаемых страницах

    авто

    Категория из одного заголовка и списка товаров редко конкурирует с развёрнутой страницей.

    Как проверитьПосчитать количество слов в основном блоке, сравнить с конкурентами.

  6. Цены на страницах совпадают с прайсом

    глазами

    Расхождение между страницей услуги и общим прайсом — прямая потеря доверия и повод для спора с клиентом.

    Как проверитьСверить значения построчно между разделами.

  7. Единый формат цен и валюты

    глазами

    Где-то «5400», где-то «5 800», где-то «руб.», где-то «р.» — мелочь, которая читается как неряшливость.

    Как проверитьПросмотреть отображение цен во всех типах блоков и таблиц.

  8. Контакты и реквизиты совпадают везде

    авто + глазами

    Разные телефоны в шапке, подвале и на странице контактов путают человека и мешают привязке к региону.

    Как проверитьСобрать телефоны, адреса и почту со всех страниц и сверить.

  9. Орфография и пунктуация

    авто

    Ошибки в заголовках и кнопках заметны сразу и дороже всего обходятся на первом экране.

    Как проверитьПрогнать тексты через проверку правописания, отдельно проверить заголовки и подписи кнопок.

  10. Актуальность дат и новостей

    авто

    Последняя новость трёхлетней давности говорит посетителю, что сайтом не занимаются.

    Как проверитьНайти самые свежие даты в разделах новостей и статей.

Скорость и Core Web Vitals 13

Скорость влияет и на позиции, и на отказы. На мобильных это решающий фактор: там приходит большая часть трафика.

  1. Основные метрики в зелёной зоне

    авто

    LCP, CLS и INP — то, что реально измеряет поиск. Оценка в отчёте вторична, метрики первичны.

    Как проверитьЗапросить PageSpeed Insights по API для мобильной и десктопной версии.

  2. Общая оценка не ниже 70

    авто

    Ниже 70 — красная зона и повод для серьёзных работ. Ориентир для нормального сайта — 80–85.

    Как проверитьВзять значение performance из отчёта для обеих версий.

  3. Нет ресурсов, блокирующих отрисовку

    авто

    Скрипты и стили, подключённые до содержимого, задерживают появление страницы на секунды.

    Как проверитьНайти синхронные подключения в head, перенести скрипты вниз или добавить defer.

  4. Включено сжатие текста

    авто

    gzip или brotli уменьшают передаваемый объём в разы. Отключённое сжатие — самая дешёвая в исправлении проблема.

    Как проверитьПроверить заголовок Content-Encoding в ответе.

  5. Изображения в современных форматах

    авто

    WebP и AVIF весят заметно меньше при том же качестве. Тяжёлый баннер на первом экране обычно и есть причина плохого LCP.

    Как проверитьСобрать изображения первого экрана, посмотреть форматы и вес.

  6. Размеры изображений под экран

    авто

    Отдавать телефону картинку шириной 2000 пикселей — впустую потраченный трафик пользователя.

    Как проверитьСравнить реальные размеры файлов с размерами отображения, проверить наличие srcset.

  7. У изображений заданы width и height

    авто

    Без явных размеров страница дёргается при загрузке, и это напрямую ухудшает CLS.

    Как проверитьНайти теги img без атрибутов размеров или без заданного соотношения сторон.

  8. Ленивая загрузка ниже первого экрана

    авто

    Картинки, которых пользователь ещё не видит, не должны конкурировать за канал с тем, что он видит.

    Как проверитьПроверить атрибут loading у изображений вне первого экрана.

  9. Минификация и удаление лишнего кода

    авто

    Неиспользуемые стили и скрипты браузер всё равно скачивает и разбирает.

    Как проверитьВзять из отчёта объём неиспользуемого CSS и JS, проверить, минифицированы ли файлы.

  10. Время до первого байта

    авто

    Медленный ответ сервера невозможно компенсировать оптимизацией на стороне браузера.

    Как проверитьИзмерить TTFB несколькими запросами, ориентир — до 600 мс.

  11. Сторонние скрипты не блокируют страницу

    авто

    Чужие виджеты, пиксели и чаты грузятся с чужих серверов и тянут страницу за собой.

    Как проверитьНайти внешние подключения, проверить наличие async или defer.

  12. Кеширование статики

    авто

    Повторный визит не должен заново скачивать логотип и стили.

    Как проверитьПроверить заголовки Cache-Control и время жизни для статических файлов.

  13. Мёртвые внешние подключения

    авто

    Заблокированный или удалённый сторонний сервис даёт долгие таймауты на каждой загрузке.

    Как проверитьПроверить коды ответа всех внешних запросов страницы.

Мобильная версия и качество вёрстки 17

Большая часть трафика приходит с телефонов, но проверяют сайт чаще всего на большом мониторе. Отсюда почти все находки этого раздела.

  1. Три контрольные ширины

    авто

    320, 768 и от 1200 пикселей — минимальный набор, на котором нужно смотреть каждую страницу.

    Как проверитьОткрыть ключевые страницы в трёх размерах и сравнить со здравым смыслом.

  2. Нет горизонтальной прокрутки

    авто

    Страница, которая ездит вбок, воспринимается как сломанная. Чаще всего виноваты таблицы и широкие картинки.

    Как проверитьСравнить ширину содержимого с шириной окна на каждой ширине.

  3. Таблицы прокручиваются внутри себя

    авто

    Широкая таблица должна прокручиваться в своём контейнере, а не тащить за собой всю страницу.

    Как проверитьНайти таблицы и проверить, есть ли у них контейнер с прокруткой.

  4. Содержимое не выходит за родителя

    авто

    Длинное слово, крупная цена или иконка не должны ломать сетку.

    Как проверитьПроверить границы блоков при подстановке длинных значений.

  5. Область нажатия не меньше 44 пикселей

    авто

    Мелкие иконки в шапке промахиваются пальцем и раздражают.

    Как проверитьИзмерить размеры кликабельных элементов на мобильной ширине.

  6. Формы помещаются в экран

    глазами

    Форма, которая не влезает, — это несостоявшаяся заявка.

    Как проверитьОткрыть каждую форму на узком экране и попробовать заполнить.

  7. Поля ввода не мельче 16 пикселей

    авто

    При меньшем размере телефон сам приближает страницу при фокусе, и вёрстка уезжает.

    Как проверитьПроверить размер шрифта у полей ввода.

  8. Меню и выпадающие списки работают пальцем

    глазами

    Наведение мышью на телефоне не существует. Всё, что раскрывается по наведению, должно раскрываться по касанию.

    Как проверитьПройти по всем уровням меню на сенсорном устройстве.

  9. Липкий хедер не съедает экран

    глазами

    На узком экране закреплённая шапка может занять треть высоты. Нужна компактная версия.

    Как проверитьПосмотреть долю экрана, занятую шапкой при прокрутке.

  10. Кнопка возврата наверх

    глазами

    На длинных страницах без неё пользователь просто уходит.

    Как проверитьПроверить наличие и появление кнопки после прокрутки.

  11. Валидатор разметки без грубых ошибок

    авто

    Незакрытые теги и дублирующиеся идентификаторы ломают разбор страницы роботами.

    Как проверитьПрогнать страницы через валидатор и отобрать ошибки, а не предупреждения.

  12. Семантические ориентиры

    авто

    Теги header, main, nav, aside и footer помогают и роботам, и программам чтения с экрана.

    Как проверитьПроверить наличие ориентиров и единственность main.

  13. Ссылки ссылками, кнопки кнопками

    авто

    Переход между страницами — тег ссылки, действие на странице — тег кнопки. Иначе ломается навигация с клавиатуры.

    Как проверитьНайти кликабельные элементы, оформленные не теми тегами.

  14. Поля формы связаны с подписями

    авто

    Без связи подпись не читается вслух и не увеличивает область нажатия.

    Как проверитьПроверить, что каждому полю соответствует подпись с привязкой.

  15. Контраст текста не ниже 4.5:1

    авто

    Светло-серый текст на цветном фоне не читается на солнце и на дешёвых экранах.

    Как проверитьПосчитать контраст для каждого текстового элемента с учётом фактического фона.

  16. Фокус виден при работе с клавиатуры

    авто

    Без видимого фокуса сайт непроходим для тех, кто не пользуется мышью.

    Как проверитьПройти по странице клавишей табуляции и посмотреть, где находится фокус.

  17. Кроссбраузерность

    глазами

    Проверять нужно в последних версиях Chrome, Firefox и Safari. Safari отличается заметнее всего.

    Как проверитьОткрыть ключевые страницы в трёх браузерах и сравнить.

Юзабилити и конверсионные элементы 19

Технически безупречный сайт может не приносить заявок. Этот раздел про то, доходит ли человек до целевого действия.

  1. Первый экран передаёт суть

    глазами

    У вас несколько секунд. Если вместо предложения там статья, пользователь уходит.

    Как проверитьПосмотреть на первый экран глазами человека, который видит сайт впервые.

  2. Акценты ведут внимание

    глазами

    Самый крупный и контрастный элемент воспринимается первым. Он должен быть самым важным, а не случайным.

    Как проверитьОценить порядок восприятия элементов, сверить с картой кликов.

  3. Хлебные крошки

    авто

    Показывают, где находится человек, и дают дополнительную перелинковку с разметкой для выдачи.

    Как проверитьПроверить наличие на вложенных страницах и корректность разметки.

  4. Активный пункт меню выделен

    глазами

    Без выделения человек теряет ориентацию в структуре.

    Как проверитьПройти по разделам и посмотреть на состояние меню.

  5. Телефон и почта кликабельны

    авто

    На телефоне номер должен набираться в одно касание.

    Как проверитьПроверить схемы tel: и mailto: в ссылках.

  6. Обязательные поля помечены

    глазами

    Иначе человек заполняет наугад и получает ошибку после отправки.

    Как проверитьОткрыть формы и посмотреть на пометки обязательных полей.

  7. Проверка данных до отправки

    глазами

    Ошибка должна появляться рядом с полем сразу, а не после перезагрузки страницы.

    Как проверитьОтправить формы с пустыми и некорректными значениями.

  8. Маска телефона и проверка почты

    глазами

    Частая беда: при неполном вводе телефона введённые цифры теряются, и человек начинает заново.

    Как проверитьВвести неполный номер, снять фокус, посмотреть, сохранились ли цифры.

  9. Понятные сообщения об ошибках

    глазами

    Сообщение должно говорить, что не так и что сделать, а не просто краснеть.

    Как проверитьПроверить текст ошибок для каждого поля.

  10. Подтверждение после отправки

    глазами

    Человек должен понимать, что заявка ушла. Отдельная страница благодарности заодно даёт цель для аналитики.

    Как проверитьОтправить форму и посмотреть, что происходит дальше.

  11. Письма доходят до адресата

    глазами

    Форма может отправляться, а письмо падать в спам или не уходить вовсе.

    Как проверитьОтправить тестовую заявку и проверить и почту менеджера, и запись в админке.

  12. Защита форм от спама

    глазами

    Без защиты менеджер тонет в мусоре и перестаёт читать заявки.

    Как проверитьПроверить наличие защиты во всех формах, а не только в главной.

  13. Фильтры и сортировки работают

    глазами

    Сброс фильтра, снятие отдельного значения, ползунок цены — типичные места, где ломается всё.

    Как проверитьПройти сценарии выбора и сброса в каталоге.

  14. Пустое состояние оформлено

    глазами

    Когда фильтр ничего не нашёл, нужен понятный текст и путь назад, а не пустая страница.

    Как проверитьЗадать заведомо невозможные условия фильтра.

  15. Цена, наличие и сроки видны

    глазами

    Отсутствие цены — главная причина ухода к конкуренту, у которого она есть.

    Как проверитьПосмотреть карточки и категории на предмет ключевой информации.

  16. Доверие подкреплено

    глазами

    Отзывы с фото, сертификаты, документы, реквизиты снимают возражения до обращения.

    Как проверитьПроверить наличие и доступность этих блоков.

  17. У файлов указан формат и размер

    глазами

    Человек должен понимать, что откроется и сколько весит, до нажатия.

    Как проверитьПроверить подписи у ссылок на скачивание.

  18. Онлайн-консультант не мешает

    глазами

    Всплывающее окно поверх кнопки заказа стоит денег, а не приносит их.

    Как проверитьПосмотреть, что перекрывает виджет на разных экранах.

  19. Карты кликов и прокрутки

    сервисы

    Показывают, доходят ли до нужного блока и жмут ли то, что не является кнопкой.

    Как проверитьРазобрать карты в системе аналитики за достаточный период.

Безопасность 13

Раздел, который в SEO-аудитах обычно пропускают, а он даёт заметные находки и хорошо выглядит в отчёте.

  1. Валидный сертификат и срок действия

    авто

    Просроченный сертификат закрывает сайт предупреждением браузера и обнуляет трафик.

    Как проверитьПроверить издателя, срок и совпадение домена.

  2. Строгий переход на HTTPS

    авто

    Заголовок HSTS запрещает браузеру открывать сайт по незащищённому протоколу.

    Как проверитьПроверить наличие Strict-Transport-Security и его параметры.

  3. Заголовки безопасности

    авто

    X-Content-Type-Options, Referrer-Policy и запрет встраивания в чужие страницы закрывают типовые векторы.

    Как проверитьПрочитать заголовки ответа и сверить с рекомендуемым набором.

  4. Смешанного содержимого нет

    авто

    Картинка или скрипт по http внутри https-страницы ломает замок в адресной строке.

    Как проверитьНайти ресурсы с незащищённым протоколом в разметке.

  5. Вывод ошибок отключён на бою

    авто

    Расширенный вывод ошибок показывает пути на сервере, версии и структуру кода. Это подарок злоумышленнику.

    Как проверитьСпровоцировать ошибку и посмотреть, что видно на странице.

  6. Cookie защищены

    авто

    Атрибуты Secure, HttpOnly и SameSite мешают перехвату сессии.

    Как проверитьРазобрать заголовки Set-Cookie.

  7. Служебные файлы недоступны

    авто

    Открытые .git, .env, дампы базы и резервные копии — самая частая причина утечек.

    Как проверитьЗапросить типовые адреса и проверить, что все отдают 404 или 403.

  8. Просмотр содержимого папок выключен

    авто

    Открытый список файлов показывает всё, что забыли убрать с сервера.

    Как проверитьЗапросить папки без индексного файла.

  9. Версии не светятся в заголовках

    авто

    Точная версия сервера и CMS позволяет подобрать готовый эксплойт.

    Как проверитьПрочитать заголовки Server, X-Powered-By и мета-теги генератора.

  10. Административная панель защищена

    глазами

    Стандартный адрес входа без ограничений — приглашение к перебору паролей.

    Как проверитьПроверить доступность типовых адресов входа и наличие ограничения попыток.

  11. CMS и модули обновлены

    глазами

    Решения пятилетней давности содержат уже закрытые в новых версиях уязвимости.

    Как проверитьПосмотреть даты обновления установленных модулей.

  12. Логи ведутся и недоступны снаружи

    глазами

    Логи нужны для разбора инцидентов, но не должны открываться по прямой ссылке.

    Как проверитьПроверить, что логирование включено, а файлы логов не отдаются по http.

  13. Формы защищены от подделки запроса

    глазами

    Без токена сторонний сайт может отправить форму от имени пользователя.

    Как проверитьПроверить наличие одноразового токена в формах.

Аналитика и отслеживание 9

Без этого раздела нельзя ответить на вопрос «что сработало». Ставится один раз, проверяется перед каждым релизом.

  1. Счётчик стоит на всех страницах

    авто

    Пропущенная часть сайта даёт искажённую картину и неверные выводы.

    Как проверитьОбойти сайт и проверить наличие кода счётчика на каждой странице.

  2. Счётчик не задублирован

    авто

    Два одинаковых счётчика удваивают визиты и обнуляют доверие к цифрам.

    Как проверитьПосчитать вхождения кода на странице.

  3. Вебвизор и карты включены

    глазами

    Запись сессий, карта кликов и карта прокрутки — основной источник материала для раздела про юзабилити.

    Как проверитьПроверить настройки в интерфейсе системы аналитики.

  4. Цели настроены

    глазами

    Отправка формы, звонок по ссылке, скачивание файла. Без целей конверсия не считается.

    Как проверитьПроверить список целей и совершить каждое действие для проверки.

  5. Электронная торговля для магазина

    глазами

    Без неё невозможно связать позиции с выручкой.

    Как проверитьПроверить передачу данных о заказах в аналитику.

  6. Панели вебмастеров подтверждены

    глазами

    Там видно индексацию, ошибки обхода и запросы, по которым показывается сайт.

    Как проверитьПроверить подтверждение прав в панелях обеих поисковых систем.

  7. Карта сайта добавлена в панель

    глазами

    Ускоряет обход новых страниц.

    Как проверитьПроверить статус карты в панели вебмастера.

  8. Счётчик не тормозит загрузку

    авто

    Синхронно подключённая аналитика отодвигает отрисовку.

    Как проверитьПроверить способ подключения кода счётчика.

  9. Мёртвые пиксели удалены

    авто

    Код заблокированного или неиспользуемого сервиса даёт ошибки и замедляет страницу.

    Как проверитьПроверить коды ответа внешних запросов и ошибки в консоли.

Анализ конкурентов 11

Помогает объяснить не только что сломано, но и почему выше стоит кто-то другой. Это часть, которую агент делает только наполовину.

  1. Динамика видимости

    сервисы

    Если видимость упала с конкретной даты, дальше ищется, что менялось в этот период.

    Как проверитьПосмотреть график запросов в топе по сервисам оценки видимости.

  2. Кто в топе по основным запросам

    глазами

    Смотреть нужно в режиме инкогнито и с правильно выбранным регионом, иначе выдача будет персонализированной.

    Как проверитьЗадать три-пять основных запросов, зафиксировать первую пятёрку.

  3. Ассортимент сопоставим

    глазами

    Если у конкурента втрое больше позиций, разница в позициях объясняется не только техникой.

    Как проверитьСравнить количество товаров в общих категориях.

  4. Карточки оформлены не хуже

    глазами

    Фотографии, характеристики, документы, наличие, сроки доставки.

    Как проверитьОткрыть по одной карточке у каждого конкурента и сравнить состав.

  5. Цены показаны открыто

    глазами

    Отсутствие цены при её наличии у конкурентов — почти всегда потеря позиций по коммерческим запросам.

    Как проверитьСравнить, где цена видна сразу, а где скрыта за формой.

  6. Отзывы и рейтинги

    глазами

    Социальные доказательства влияют и на конверсию, и на коммерческие факторы ранжирования.

    Как проверитьПосмотреть наличие и количество отзывов у себя и у конкурентов.

  7. Приёмы в заголовках конкурентов

    авто + глазами

    Разбор title топа показывает рабочую формулу: ключ, цена, город, установка, производитель.

    Как проверитьСобрать title первой десятки по запросу и разложить на составляющие.

  8. Структура каталога и посадочные

    глазами

    Отдельные страницы под фильтры и сочетания свойств дают охват, которого нет у плоского каталога.

    Как проверитьСравнить глубину и логику каталогов.

  9. Ссылочный профиль

    сервисы

    Число ссылающихся доменов, доля покупных ссылок и плавность динамики. Резкий рост так же плох, как и падение.

    Как проверитьПроверить показатели по сервисам анализа ссылок для себя и для топа.

  10. Скорость конкурентов

    авто

    Абсолютные цифры менее важны, чем разрыв: если у всех 40, ваши 55 уже преимущество.

    Как проверитьПрогнать конкурентов через тот же инструмент измерения скорости.

  11. Коммерческие факторы

    глазами

    Доставка, оплата, гарантии, реквизиты, режим работы, филиалы, карточка организации в справочнике.

    Как проверитьПройти по списку и отметить, что есть у конкурентов и чего нет у вас.

Проверки после внедрения 13

Отдельный прогон через несколько дней после релиза. Половина проблем в SEO появляется не сама по себе, а в момент выкладки правок.

  1. Правки доехали до боевого сайта

    авто

    Классика: всё сделано и проверено на тестовом сервере, а на бой не выложено.

    Как проверитьПовторить прогон по боевому адресу и сравнить с прошлым снимком.

  2. robots.txt не закрыл лишнего

    авто

    Тестовый robots с полным запретом, случайно выложенный на бой, убирает сайт из поиска за сутки.

    Как проверитьСверить содержимое файла с эталоном до релиза.

  3. Мета-теги не слетели

    авто

    Обновление шаблона часто сбрасывает вручную заполненные заголовки.

    Как проверитьСравнить title и description со снимком предыдущего прогона.

  4. Редиректы не образовали цепочек

    авто

    Новые правила накладываются на старые и дают два-три шага вместо одного, а иногда петлю.

    Как проверитьПройти по цепочкам для типовых адресов.

  5. Коды ответа не изменились

    авто

    Страницы, отдававшие 200, должны отдавать 200. Появление новых 404 и 500 — повод откатывать.

    Как проверитьСравнить коды ответа со снимком до релиза.

  6. Карта сайта перегенерировалась

    авто

    Новые страницы должны появиться в карте, удалённые — исчезнуть.

    Как проверитьСравнить состав карты и даты изменения.

  7. Скорость не упала

    авто

    Новый скрипт или неоптимизированная картинка легко уводят метрики в красную зону.

    Как проверитьПовторить измерение и сравнить с прошлыми значениями.

  8. Формы по-прежнему работают

    глазами

    Проверять после каждого релиза, потому что ломается это тихо и замечается по отсутствию заявок.

    Как проверитьОтправить тестовую заявку в каждой форме и проверить получение.

  9. Счётчики на месте

    авто

    Аналитика теряется при обновлении шаблона чаще, чем кажется.

    Как проверитьПроверить наличие кода на всех типах страниц.

  10. Новых битых ссылок не появилось

    авто

    Смена адресов разделов оставляет старые ссылки в текстах и меню.

    Как проверитьПовторный обход и сравнение списка ошибок.

  11. Новых дублей не появилось

    авто

    Новые фильтры и сортировки — постоянный источник дублей.

    Как проверитьСравнить число уникальных страниц и адресов с параметрами.

  12. Индексация не обвалилась

    сервисы

    Проверяется через одну-две недели: число страниц в поиске не должно резко упасть.

    Как проверитьПосмотреть динамику в панели вебмастера.

  13. Позиции через месяц

    сервисы

    Раньше делать выводы бессмысленно: изменения доходят до выдачи не мгновенно.

    Как проверитьСнять позиции по опорному списку запросов и сравнить.

Правила

Формулировки замечаний вынесены из кода в файлы данных: 113 правил, у каждого свой постоянный идентификатор. Это даёт две вещи. Текст можно править, не трогая логику проверок. И два прогона можно сравнить между собой — видно, что исправлено, а что появилось.

Как выглядит находка

критично

Нет счётчика аналитики

На странице не найдено ни одной системы аналитики.

Почему это плохоБез счётчика невозможно ответить на вопрос «что сработало». Не видно ни источников трафика, ни поведения людей, ни конверсии — то есть любая работа над сайтом делается вслепую.

Что делатьПоставьте Яндекс.Метрику или другую систему аналитики и включите запись действий пользователей.

важно

Одинаковые заголовки у разных страниц

Title «{value}» повторяется на {count}: {pages}

Почему это плохоДля поисковика это прямой сигнал, что страницы дублируют друг друга. Часть из них выпадет из выдачи, и какая именно останется — решать будет не владелец сайта.

Что делатьУникализируйте заголовки. На каталогах помогает шаблон на основе H1 с добавлением уточнений.

мелочь

Описание повторяет заголовок

Описание дословно повторяет title.

Почему это плохоЧеловек дважды читает одно и то же вместо того, чтобы получить дополнительную причину кликнуть.

Что делатьПерепишите описание так, чтобы оно дополняло заголовок, а не повторяло его.

Запуск

Нужен Node.js 22 или новее. Ключи не обязательны: без них пропускается только измерение скорости.

git clone https://github.com/qa-novchenkova/seo-revizor.git
cd seo-revizor
npm install
npm run check meta https://example.com/

Файл .mcp.json уже в репозитории — откройте папку в Claude Code или другом клиенте с поддержкой MCP, и инструменты появятся в списке. Дальше можно просто попросить: «следуй AGENT.md и проверь сайт такой-то».

Полное описание, устройство и разбор каждого файла — в README репозитория.
