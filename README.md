# Ревизор

MCP-сервер и агент, который проверяет сайт по чек-листу и собирает отчёт.

Проект собирается по этапам. Сейчас готов **этап 3**: пять инструментов
и чек-лист из 53 правил, вынесенный из кода в файлы данных.

## Инструменты

| Инструмент | Что делает |
|---|---|
| `check_url` | Код ответа, полная цепочка редиректов, ключевые заголовки, время ответа |
| `check_meta` | Title, описание, заголовки H1–H6 и их иерархия, canonical, Open Graph, Schema.org, alt у изображений |
| `check_robots` | robots.txt: группы правил, запреты, директивы Sitemap, полное закрытие сайта |
| `check_sitemap` | sitemap.xml: список адресов, карта карт, дубли, чужие домены, даты изменения |
| `list_rules` | Весь чек-лист: идентификатор, важность, формулировка, объяснение и способ исправления |

Вместе они закрывают часть чек-листов «Индексация и техническая база»
и «Мета-теги и заголовки».

Отдельно ловится случай, когда страница собирается скриптами: в исходном HTML
нет ни заголовков, ни текста, и поисковик видит пустой каркас.

## Устройство

```
src/rules/*.json      чек-лист: формулировки, важность, объяснения, способы исправления
src/rules/index.js    реестр правил: загрузка, проверка на дубли идентификаторов
src/lib/http.js       сетевой слой: запрос с повтором, таймаут, ограничение объёма
src/lib/findings.js   сбор находок: подстановка значений в шаблон, сортировка по важности
src/lib/text.js       формы слов по числу: «21 символ», «52 символа»
src/lib/sample.js     представительная выборка страниц по типам
src/checks/url.js     |
src/checks/meta.js    |  проверки — обычные функции, ничего не знают про MCP
src/checks/robots.js  |
src/checks/sitemap.js |
src/server.js         оболочка MCP: объявляет инструменты и принимает вызовы
test/check.js         запуск проверок напрямую, без модели
test/mcp.js           разговор с сервером по протоколу вручную, без Claude Code
.mcp.json             подключение сервера к Claude Code
```

## Правила отдельно от кода

Проверка фиксирует только факт: сработало правило `redirect-chain`, количество — три.
Формулировка, важность и объяснение берутся из `src/rules/*.json`.

Это даёт три вещи:

1. Текст замечания правится без риска сломать логику.
2. У каждого правила постоянный идентификатор — по нему можно сравнить два прогона
   и понять, что починили, а что появилось.
3. К правилу приложены «почему это плохо» и «что делать», поэтому отчёт объясняет,
   а не просто перечисляет.

Каждая находка возвращается с полями `id`, `severity`, `title`, `message`, `why`, `fix`
и сортируется по важности: критично, важно, мелочь.

Логика намеренно отделена от протокола. Если функция неправильно работает
в `test/check.js`, через MCP она правильнее не станет — отлаживать нужно там.
Благодаря этому же те же функции можно будет подключить к телеграм-боту,
не переписывая.

## Запуск

Одна проверка напрямую:

```bash
npm run check meta https://example.com/
```

Доступны `url`, `meta`, `robots`, `sitemap`.

Разговор с сервером по протоколу, с цепочкой из четырёх вызовов:

```bash
npm run mcp https://example.com/
```

## Подключение к Claude Code

Файл `.mcp.json` уже в репозитории. Откройте папку проекта в Claude Code
и перезапустите его — сервер подхватится, инструменты появятся в списке.

Если сервер не запустился, замените в `.mcp.json` относительный путь на полный:

```json
{ "mcpServers": { "seo-revizor": { "command": "node", "args": ["D:/QQQAAA/seo-revizor/src/server.js"] } } }
```

## Важно при доработке

Общение с клиентом идёт через стандартный ввод-вывод. `console.log` пишет
в тот же поток и ломает протокол — для отладки используйте только `console.error`.
